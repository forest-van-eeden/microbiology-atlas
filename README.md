# Microbiology Atlas

Purchasing-planning tool for college and university microbiology teaching labs: a stock-and-pack item planner, a semester budget, a review checklist, a downloadable report, and optional consent-based sharing of that report with the project team. Run by Forest van Eeden.

- What's built vs planned: `docs/IMPLEMENTATION-STATUS.md`
- Sitemap: `docs/microbiology-atlas-sitemap.md`

## Layout

```
dist/                     static site, served as-is (no build step)
  index.html              the planner
  about|privacy|disclosures|contact|404.html   generated by scripts/pages.py
  atlas-core.js           ES module: formulas, validation, report snapshot + renderers (browser, Function, tests)
  app.js                  page wiring and the sharing flow
  _headers                security headers (CSP etc.) for Cloudflare Pages
functions/                Cloudflare Pages Functions
  api/config.js           GET  /api/config
  api/reports/share.js    POST /api/reports/share
  api/reports/status.js   GET  /api/reports/status
  _lib/share.js           the logic (pure; unit-tested)
scripts/dev-server.mjs    local stand-in for Cloudflare Pages (clean URLs, _headers, 404, /api)
scripts/pages.py          regenerates the information pages
test/unit/                node:test — formulas, validation, escaping, report, share service
test/browser/             node:test + Playwright — the real site in headless Chromium
```

## Run locally

```
npm run serve            # http://127.0.0.1:8765/  (sharing shows as unavailable without credentials)
npm test                 # unit tests (Node 18+; no dependencies)
npm run test:browser     # needs: npm i -D playwright@1.56.0 && npx playwright install chromium
python3 scripts/pages.py # after editing About/Privacy/Disclosures/Contact text
```

## Deploying to Cloudflare Pages

One-time setup in the Cloudflare dashboard:

1. **Workers & Pages → Create → Pages → Connect to Git**, choose this repository.
   Build command: *(none)*. Build output directory: `dist`. Production branch: `main`.
2. **Workers & Pages → KV → Create namespace** named `atlas-share-log`.
3. In the Pages project → **Settings → Bindings → Add → KV namespace**: variable name `SHARE_LOG`, namespace `atlas-share-log` (Production and Preview).
4. **Settings → Variables and secrets** (Production):
   - `AGENTMAIL_API_KEY` — type **Secret**. Create the key in the AgentMail console. Never put it in the repo or a chat.
   - `SHARING_ENABLED` — `false` at first. Set to `true` only after the end-to-end test below.
   - Optional: `AGENTMAIL_SENDER_INBOX` (defaults to the team inbox), `AGENTMAIL_API_BASE` (defaults to `https://api.agentmail.to/v0`).
5. Redeploy (Deployments → Retry) after changing variables.

Until all of `SHARING_ENABLED=true`, `AGENTMAIL_API_KEY` and the `SHARE_LOG` binding exist, `/api/config` reports sharing as off and the page shows no checkbox. Downloads always work.

### End-to-end check before enabling sharing for visitors

1. Set `SHARING_ENABLED=true` on a **Preview** deployment, or briefly on Production.
2. Open the site, tick “Share a copy…”, download a report with non-sensitive test values.
3. Confirm in the AgentMail console that the message arrived in `microbiology-atlas-team@agentmail.to`, the attachment opens, and it matches the downloaded file.
4. Only then leave `SHARING_ENABLED=true` on Production.

If the team inbox can't send to itself, set `AGENTMAIL_SENDER_INBOX` to a separate sending inbox and repeat.

## Rules for changes

- Formula changes bump `FORMULA_VERSION` in `atlas-core.js` and update unit tests.
- Changing the sharing wording or recipient bumps `CONSENT_VERSION` and updates `/privacy`.
- All user text goes through `escapeHtml` / `escapeMarkdown` / `csvCell`.
- The server rebuilds reports from raw inputs; never trust client totals or HTML.
